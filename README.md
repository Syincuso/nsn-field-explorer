# NSN Field Explorer (for NetSuite Next)

Shows the field ID, label, type and current value of every body field, plus sublist field IDs and line values, on any NetSuite record page. It finds the form inside NetSuite Next's iframe automatically, and works in both view and edit mode. It is a read-only browser extension for Chrome, Edge and Firefox, released under the [Apache License 2.0](LICENSE).

## Use it as a browser extension (Edge or Chrome)
1. Get the code (`git clone https://github.com/Syincuso-LLC/nsn-field-explorer.git`, or download it as a zip from GitHub) and keep the folder somewhere permanent; the browser loads the extension from it every time it starts.
2. Go to `edge://extensions` (Edge) or `chrome://extensions` (Chrome) and turn on **Developer mode**.
3. Click **Load unpacked** and pick the `extension` folder inside this folder.
4. Pin it: click the puzzle-piece **Extensions** button in the toolbar, then the pin next to **NSN Field Explorer**.
5. On a NetSuite record, click the **NSN Field Explorer** button in the browser toolbar or press **Alt+Shift+F**. Press it again to close the panel.

If the shortcut does nothing, set it at `edge://extensions/shortcuts` (or `chrome://extensions/shortcuts`). If the button shows a red **!**, the browser couldn't run the script on that tab; hover the button to see why. After updating the files, click the reload arrow on the extension's card.

## Use it in Firefox (140 or later)
- **To try it:** go to `about:debugging#/runtime/this-firefox`, click **Load Temporary Add-on…** and pick `extension/manifest.json`. Firefox removes a temporary add-on when it restarts.
- **To keep it installed:** Firefox only installs signed add-ons. Upload a zip of the `extension` folder to [addons.mozilla.org](https://addons.mozilla.org/developers/) as an unlisted add-on. Mozilla signs it without publishing it, and you share the signed `.xpi`.
- The same `extension` folder serves Chrome, Edge and Firefox: Firefox reads `background.scripts` and `browser_specific_settings`, and Chrome and Edge ignore them. The add-on ID is `nsn-field-explorer@syincuso.com`. Once the add-on is on addons.mozilla.org, this ID can never change.
- The shortcut can be changed under **Manage Extension Shortcuts** in the gear menu of `about:addons`.
- On Firefox's own pages (`about:…`) the button does nothing. On sites Firefox keeps extensions away from (such as addons.mozilla.org) it shows the red **!**.

## Privacy
The extension sends nothing anywhere. It runs only when you click its button or press the shortcut, reads the NetSuite page in your browser, and keeps its settings (and a pinned record, until the tab closes) in the browser's storage for the NetSuite site. The full policy is in [store/PRIVACY.md](store/PRIVACY.md).

## What the panel does
Click **?** in the panel's title bar for a short help page inside the panel.

- **Toolbar:** one row under the title bar holds the section switch (**Body**, **Sublists**, **Not on form**, plus **All** while searching and **Compare** once a record is pinned or compared with its saved version), the search box, and four icon buttons: **Filters**, **Inspect**, **Pin** and **View Raw** (hover one for its name). On a narrow panel it wraps onto two rows, and the Type column moves under each label.

- **Body tab:** every field with its field ID, label, type and value. Select fields show the display text with the internal ID underneath. Multi-select values are separated by ` | ` (for example `Red | Blue` over `1 | 2`), in the panel and in every copy and export. Custom fields (`cust...`) are bold. `custpage...` fields are purple as well: a script (for example a beforeLoad user event) added them to the form, and they are not saved on the record, so searches, SuiteQL and `record.load` don't see them. Required fields have a red `*`.
- **Sublists tab:** a row of buttons under the toolbar, one per sublist with its line count (for example `item 3`; hovering shows the page's name for the sublist). Sublists with lines come first; empty ones fold into a **+N empty** button that opens them (while searching, **+N more** for the ones with no matches). Pick one to see every column's field ID with one column per line (first 50 lines).
- **Loading indicator:** while values are still loading (the saved record in view mode, or names fetched in the background), a thin bar moves under the title bar and a small spinner sits next to each value still on its way. Both go away when everything is in.
- **Hidden fields:** fields the form sets to display type Hidden are listed in Body too, with type `…, hidden`. That covers every custom field, and in view mode also standard ones such as Amount, Currency, Approval Status, Next Approver and the created/last-modified dates. The record type the title bar shows is listed too, as `baserecordtype` (Record Type), so it can be searched, copied and exported. The page's own plumbing (`nluser`, `nsbrowserenv`, …) is left out, and so are the other type codes (`type`, `dbstrantype`, `ntype`). In edit mode, standard hidden fields only appear after you open Not on form, which loads the saved record that tells them apart from plumbing.
- **Not on form tab:** fields the saved record has that the page doesn't contain at all (for example Custom Form or a custom checkbox the form leaves out). Fields with no label have a green field ID instead of dark red (gold in the dark theme): they are mostly NetSuite internals (`sys_id`, `haslines`…), but they stay listed and searchable. In edit mode, opening this tab loads the saved record, so it shows saved values, not unsaved edits.
- **Settings (⚙ in the title bar):** pick the theme (Auto follows the system, or Light or Dark), turn on **Compact view** for smaller text and tighter rows, and set **Click copies** (below). All three are remembered. Esc or a click anywhere else closes the menu.
- **Pin and Compare:** click the **Pin** button, then the **Pin …** button in its menu (it names the record), to remember the record on the page. The button is highlighted while a record is pinned, and its menu then offers **Open Compare**, **Unpin**, or pinning the record on the page instead. Then open another record, or change this one, and the **Compare** tab lists the differences: body fields added, removed or changed (Pinned and Current values side by side), and per sublist the lines added or removed and the cells changed. The Change column is green for added, red for removed and gold for changed. When you compare a record with an earlier pin of itself, lines are matched by their line key, so a reordered or inserted line isn't reported as a change; two different records are compared line by line in order. Equal numbers in a different format (`100` and `100.00`) count as the same. **Show unchanged** also lists the body fields that match. The search, filters, sorting, copy and View Raw CSV work on the comparison too. The pin lives in this browser tab only (`sessionStorage`) until you close the tab or click **Unpin**; it holds up to 500 lines per sublist. In edit mode on a saved record, the Pin menu also offers **Compare with the saved record**: Compare then lists what you have changed on the form and not saved yet (**Saved record** next to **This form (unsaved edits)**), without pinning anything. It loads the saved record the way Not on form does, and compares only the fields and sublist columns the saved record has (not hidden fields or the created and last modified dates), so an untouched form shows no differences. Slow values (date-time fields, the saved sublist lines, saved names of changed line items) are read in the background and added as they arrive; a saved name the background search can't find shows as its internal ID. If a record is pinned as well, a switch above the comparison flips between **Pinned record** and **Saved record**. It isn't offered in view mode (the page already shows the saved values) or on a new record that hasn't been saved.
- **Collapse and move:** drag the title bar to move the panel, drag any edge or corner to resize it (like a window), and click **–** to collapse it to the title bar (**+** expands it). Its position, size and collapsed state are remembered for next time.
- **Title bar copy:** the title bar shows the record type, the internal ID and the document number (for example `vendorbill #1001 VB-1001`). Click one, or Tab to it and press Enter, to copy its plain value (`1001`, without the `#`), whatever **Click copies** is set to. A new record that hasn't been saved shows only its type.
- **Search:** type in the search box to look through every section at once: Body, all sublists and Not on form (when the saved record is loaded). An **All** tab lists the matches with a Section column (for example `Sublist: item`), and each tab shows how many matches it has. Click a tab to see just that section's matches; clear the box, or click the red **×** in it, to go back. The matching text is highlighted (champagne with a gold underline; firebrick with a red underline in the dark theme) in the field IDs, labels and values on every tab, Compare included; copies and View Raw are unaffected.
- **Filters** (the button with three lines): Hide empty, and **Fields**: All, Custom (custom fields and segments: `custbody…`, `custcol…`, `custentity…`, `cseg…` and so on) or Standard (everything else, including Custom Form). A red dot on the button means a filter is on, and **Clear filters** turns them all off.
- **Sorting:** click a column header to sort by it (▲), click again to reverse (▼), and a third time to go back to the page's order. Empty values go last. View Raw CSV uses the order shown (except a sublist CSV, which keeps line order).
- **Column widths:** drag the right edge of a column header to make the column wider or narrower (40 px at least). Once you've resized a column, the table may be wider than the panel; scroll sideways to see the rest. Widths are remembered for each tab (Body and Not on form share theirs) the next time the panel opens. Double-click a header edge to go back to automatic widths for that tab.
- **Inspect:** hover any field or sublist cell on the form to see its ID, label, type and value. Click copies it. A strip under the toolbar shows while it is on; Esc or its **Stop** button turns Inspect off.
- **Show on the form (eye icon):** on Body, Sublists or the search results, click the grey eye at the end of the field ID. The panel opens the NetSuite tab the field is on (it only switches tabs, it never changes a value), scrolls to the field (or, for a sublist column, its header) and highlights it with a rounded red ring for a moment. A field or column gets the eye only if it can be shown: one that is just on another tab or subtab does, but one the form hides some other way (display type hidden, a hidden column) doesn't, and neither do Not on form fields.
- **Click copies** (in Settings): choose what clicking a field ID copies: Field ID, SuiteScript 1.0 (`nlapiGetFieldValue(...)`) or SuiteScript 2.x (`rec.getValue({ fieldId: ... })`).
- **Keyboard and screen readers:** everything works without a mouse. Tab moves between the controls; in the section switch and the sublist row, Left and Right (or Home and End) pick a section or sublist. The table is one Tab stop: the arrow keys move between cells (Right from a field ID reaches its eye and setup arrow), and Enter or Space on a column header sorts, and on a field ID or value copies it, the same as a click. The JSON tree in View Raw is one Tab stop too: Up and Down move, Right opens an item (or moves into an open one), Left closes it (or moves to its parent), Home and End jump to the first and last item, and Enter or Space opens or closes an item, or copies a value. Opening Settings, Filters or Pin moves focus into the menu, and Esc closes it and goes back to its button. Focus shows as a firebrick outline (gold in the dark theme). Tabs, sort order, the table and the JSON tree are marked up for screen readers (ARIA tabs, `aria-sort`, a read-only grid, an ARIA tree).
- **Refresh** (↻ in the title bar) reads the form, the saved record and the custom field setup links again.
- **Custom field setup (arrow icon):** on a custom field or custom segment (`custbody…`, `custcol…`, `custentity…`, `custitem…`, `custevent…`, `custrecord…`, `cseg…`), click the grey arrow after the field ID to open its setup page in a new tab. The panel looks the IDs up in the background with one SuiteQL query (read-only), so the arrows appear a moment after the table. Fields added by scripts (`custpage…`), script parameters and workflow fields have no setup page. If your role can't read custom field definitions, there are no arrows and the footer says why (hover it for NetSuite's own message); custom segments still get their arrows if only custom fields are refused.
- **Records Catalog** (in the panel's footer): opens the current record type in your account's Records Catalog in a new tab (custom record types too).
- **Syincuso:** the mark in the title bar, **by SYiNCUSO** in the footer and Help > About link to [syincuso.com](https://syincuso.com), the maker of NSN Field Explorer, in a new tab. About also gives info@syincuso.com.
- **View Raw:** shows the record as JSON, CSV or XML right in the panel. Pick the format at the top; **Copy** copies the format you're viewing, **Download** saves it as a file named after the record (for example `vendorbill-1001.json`, or `vendorbill-new.json` for an unsaved record), and **Close** goes back to the fields. On the **Body** tab, Download on the CSV first asks whether to save the sublists too: **Body and sublists** saves the Body CSV plus one CSV per sublist with lines (one row per line, named like `vendorbill-1001-item.csv`), a moment apart; the first time, the browser may ask you to allow several downloads from the site. **Body only** saves just the Body CSV, and **Cancel** saves nothing. Downloaded CSV starts with a byte order mark so Excel shows accented characters correctly. The CSV view is the current table, except on the **Sublists** tab: there it is the sublist you picked as a table of its own, one row per line and one column per field (`line_number` first, then the field IDs; NetSuite's own `line` field, when the sublist has one, stays an ordinary column), with every line up to 500 (not just the 50 the panel shows), in line order whatever the sort. Each cell holds what the panel shows, so a list field holds the name, not the internal ID (JSON and XML have both). The search and filters pick the columns, never the lines. It downloads as `<type>-<id>-<sublist>.csv` (for example `vendorbill-1001-item.csv`), and the footer and the toast say how many lines it holds (`item, all 120 lines`, or `item, first 500 of 812 lines`). A note under the format buttons says which table the CSV is; on the other tabs it points to the Sublists tab for a sublist with every line, with a link that goes there. JSON and XML cover the record's data (body fields, including hidden ones, and every sublist), and the search, Hide empty and the Fields filter apply to them too: only matching body fields, and only matching sublist fields on every line. A filtered export says so (a `filters` entry in JSON, a comment in XML).
- **JSON tree:** with JSON picked, the **Tree** / **Text** switch next to the formats shows the same JSON as an outline instead of text (your choice is remembered). The top level (`record`, `filters` when a filter is on, `body` and `sublists`) starts open, and so does each sublist of up to 50 lines (a longer one shows `120 lines` until you open it); each field's details (label, type, value, text) start open too, while each line (`Line 1`, `Line 2`…) starts closed with a one-line preview, and opening a line shows its fields in full. A closed item shows a preview such as `{label: "Vendor", type: "select", value: "12", text: "Acme"}`. What you open stays open while the panel shows the same record (names arriving in the background don't close anything); another record, or Refresh, starts from these defaults again. Click a name to open or close it, or a value to copy it. Field names are dark red (gold in the dark theme), text green, numbers purple, true and false gold, and null grey. Copy and Download still give the JSON text, exactly as in Text view, and the search and filters apply to the tree as they do to the text.
- In CSV, values that would run as formulas in Excel are prefixed with `'`. If names are still loading when you click Copy or Download, it waits for them (up to 3 seconds).

## View mode
When a record is open in view mode, NetSuite doesn't give the page live field values. The panel then loads the saved record once (read-only, through NetSuite's own `N/record` module), so you still get real values, dropdown names and every sublist line. The footer says "view mode: values from the saved record". If the record can't be loaded (for example, the role can't view it that way), the panel shows the page text instead and the footer says why. **Refresh** loads it again.

## Notes
- It only reads. It never changes field values or saves anything.
- NetSuite blocks inline styles, so the panel is styled through the browser's stylesheet API. If NetSuite changes its page structure, the field lookup (`data-field-name`, `data-nsps-*`, `getMachineByName`) is the part most likely to need an update.

## Developing
You need [Node.js](https://nodejs.org/) 20 or later and Google Chrome (the tests drive your installed Chrome through Playwright, not a downloaded Chromium).

```sh
git clone https://github.com/Syincuso-LLC/nsn-field-explorer.git
cd nsn-field-explorer
npm ci           # installs Playwright, the only dependency (for the tests)
npm run build    # checks ns-field-explorer.js and copies it into extension/
npm test         # runs the tests in real Chrome against mock NetSuite pages
```

`node tests/run.mjs <filter>` runs only the tests whose name contains the filter; `HEADED=1` shows the browser.

| Path | What it is |
|---|---|
| `ns-field-explorer.js` | The panel: one self-contained script, and the file to edit. `npm run build` copies it to `extension/`, and the two copies must stay identical. |
| `extension/` | The extension itself (manifest, background script, icons, and the built copy of the panel). |
| `tests/` | `run.mjs` and the mock NetSuite pages in `tests/fixtures/`, served with a NetSuite-style Content Security Policy. |
| `tools/` | The build script, a demo server (`node tools/demo.mjs`, a mock vendor bill on http://127.0.0.1:8642/), the store video and thumbnail recorders, a code provenance check, and the icon generator (`make-icons.ps1`, Windows only). |
| `store/` | The privacy policy, the store images and the demo page. |
