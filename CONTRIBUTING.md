# Contributing

Thanks for helping. Bug reports, ideas and pull requests are all welcome. For anything bigger than a small fix, open an issue first so we can agree on the approach.

## Setup
You need Node.js 20 or later and Google Chrome. See [Developing](README.md#developing) in the README.

```sh
npm ci
npm run build
npm test
```

## The workflow
1. Edit `ns-field-explorer.js` in the repository root. It is the only copy to edit.
2. Run `npm run build`. It checks the file and copies it to `extension/ns-field-explorer.js`; commit both, byte-identical.
3. Run `npm test` (or `node tests/run.mjs <name filter>` while you work; `HEADED=1` shows the browser). Add or update a test for any change in behavior; the mock NetSuite pages are in `tests/fixtures/`.
4. When the behavior changes, bump `version` in `extension/manifest.json`, and update the README and the panel's Help (`HELP_HTML`) if a feature changed.

## Rules the code depends on
- **Read-only.** The panel never sets a field value, saves or submits anything.
- **Pure ASCII.** Write any other character in `ns-field-explorer.js` as a `\uXXXX` escape; Chrome and Edge refuse to inject a file containing some characters, and the toolbar button then silently does nothing. `node tools/asciify.js` rewrites stray characters, and the build fails on any.
- **One style.** The script is one self-contained IIFE in ES5 style (`var`, `function`, no arrow functions or template literals). Keep it that way.
- **NetSuite's Content Security Policy** blocks inline `<style>` and `style="..."`. The panel is styled through a constructable stylesheet in a shadow root; set dynamic styles through the CSSOM (`el.style.x = ...`), never in HTML strings or with `setAttribute('style', ...)`. The test pages use the same policy, so a violation fails the tests.
- **Untrusted page data.** Escape everything put into HTML (`esc`, or `hl` for search highlighting). Only list or use field and sublist IDs that pass `validId` (`^[A-Za-z0-9_]+$`). Maps keyed by an ID are `newMap()` (`Object.create(null)`) read with `has(map, id)`, because IDs such as `__proto__` or `constructor` are valid.
- **No blocking calls in a render.** On real NetSuite, `record.getText` and some `getValue` calls are synchronous server round trips. Read names from the page, or in the background as the existing code does.
- **Permissions stay `activeTab` and `scripting`**: no host permissions, no content scripts, no network requests of the extension's own.
- **Clean up.** Every listener added to the page or the form's frame is removed when the panel closes (`cleanupFns`).

## Other field explorers
NSN Field Explorer was inspired by other NetSuite field explorers but uses none of their code, and one of them has a license that forbids reuse in a competing product. Take ideas, never code: don't copy, translate or closely paraphrase code from another extension. `node tools/provenance-check.mjs <folder of their files>` checks for copied code, including renamed and rewritten copies.

## Testing on real NetSuite
Use your own development or sandbox account, never a customer's account, and don't save records while testing. Don't include real account IDs, record data or screenshots from a real account in an issue or pull request; reproduce the problem on a mock page in `tests/fixtures/` where you can.
